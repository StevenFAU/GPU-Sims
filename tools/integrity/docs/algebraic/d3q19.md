# Algebraic ground-truth: D3Q19 lattice Boltzmann constants

> **Registry entry:** `[Algebraic_D3Q19]` in `tools/integrity/docs/ground-truth-sources.md`.
> **Used by checks:** `cat3.d3q19-velocity-set`, `cat3.d3q19-weights`, `cat3.d3q19-equilibrium`.
> **Scope:** Defines the 19 velocity vectors, the 3 weight values, and the
> equilibrium-distribution evaluator at canonical test points for the D3Q19
> BGK lattice Boltzmann method used by Phase 12 (`volumetric-grid/lattice-boltzmann/`).
> **Companion reference:** `[Krueger]` registry entry covers the BGK
> *equation form* and halfway bounce-back *convention*; this document covers
> the 3D-specific *constants and ordering*. The two are paired.

---

## 1. Why algebraic, not vendored

The Krüger textbook companion code (`references/lbm-principles-practice/`,
`[Krueger]` registry entry) is D2Q9 only. No license-compatible permissively-
licensed source ships a D3Q19 reference implementation we can vendor as a
literal byte-for-byte anchor at a pinned SHA. waLBerla (GPLv3), OpenLB
(GPLv2-or-later), and Palabos (AGPLv3) all carry GPL-family contagion
incompatible with MIT vendoring. XLB (Apache-2.0) has D3Q19 but is Python
(JAX/Warp), so byte-for-byte transcription to GLSL is a translation step
that defeats the purpose of literal anchoring.

The 19 velocity vectors and 3 weight values are, however, mathematically
overdetermined: they fall out of (a) the {−1, 0, 1}³ subset with squared L2
norm ≤ 2, and (b) the isotropy + normalization constraints on the discrete
velocity set's first two moments. We derive them from first principles, pin
the result in this document, and verify GPU-Sims' implementation against
this derivation via cat3 numerical checks.

This is the same posture as `[Algebraic_Morton30]` in the same registry:
no vendor root, derivation in `tools/integrity/docs/algebraic/`, check
modules consume the derivation as the source of truth.

## 2. The D3Q19 velocity set

### 2.1 Definition

Let **C** ⊂ ℤ³ be the set of integer-valued velocity vectors **c**_i for
the D3Q19 lattice. Then:

> **C** = { **c** ∈ {−1, 0, 1}³ : ‖**c**‖² ≤ 2 }

where ‖**c**‖² = c_x² + c_y² + c_z² is the squared L2 norm.

Counting by squared norm:

| ‖**c**‖² | Description | Count | Members |
|---:|---|---:|---|
| 0 | rest vector | 1 | (0, 0, 0) |
| 1 | face neighbors (one nonzero component) | 6 | (±1, 0, 0), (0, ±1, 0), (0, 0, ±1) |
| 2 | edge neighbors (two nonzero components) | 12 | (±1, ±1, 0), (±1, 0, ±1), (0, ±1, ±1) |
| **Total** | | **19** | |

Excluded: the 8 corner vectors (±1, ±1, ±1) with ‖**c**‖² = 3. Including
those would give D3Q27.

### 2.2 GPU-Sims canonical ordering (v1 convention)

The Krüger probe (`docs/diagnostics/_audits/phase12_lbm_predraft_probe_2026-05-15_architect1.md`)
established that no canonical direction-ordering convention exists across
the LBM literature — chapter13/cpu, chapter13/cpu_intro, chapter5 MATLAB,
and chapter8/cylinder.cpp all use mutually-incompatible orderings. We
therefore pick our own and bank it here. The ordering is:

| i | **c**_i = (c_x, c_y, c_z) | ‖**c**_i‖² | Class |
|--:|:---|--:|:---|
| 0 | (0, 0, 0) | 0 | rest |
| 1 | (+1, 0, 0) | 1 | face +x |
| 2 | (−1, 0, 0) | 1 | face −x |
| 3 | (0, +1, 0) | 1 | face +y |
| 4 | (0, −1, 0) | 1 | face −y |
| 5 | (0, 0, +1) | 1 | face +z |
| 6 | (0, 0, −1) | 1 | face −z |
| 7 | (+1, +1, 0) | 2 | edge xy++ |
| 8 | (+1, −1, 0) | 2 | edge xy+− |
| 9 | (−1, +1, 0) | 2 | edge xy−+ |
| 10 | (−1, −1, 0) | 2 | edge xy−− |
| 11 | (+1, 0, +1) | 2 | edge xz++ |
| 12 | (+1, 0, −1) | 2 | edge xz+− |
| 13 | (−1, 0, +1) | 2 | edge xz−+ |
| 14 | (−1, 0, −1) | 2 | edge xz−− |
| 15 | (0, +1, +1) | 2 | edge yz++ |
| 16 | (0, +1, −1) | 2 | edge yz+− |
| 17 | (0, −1, +1) | 2 | edge yz−+ |
| 18 | (0, −1, −1) | 2 | edge yz−− |

**Opposite-direction pairs** (the involution **c**_i ↔ −**c**_i, needed for
halfway bounce-back): (1,2), (3,4), (5,6), (7,10), (8,9), (11,14), (12,13),
(15,18), (16,17). Direction 0 is its own opposite (the rest vector).

### 2.3 Sanity checks

Independent of any external source, the set defined above satisfies:

- **Cardinality:** 1 + 6 + 12 = 19. ✓
- **Symmetry under negation:** for every **c**_i ∈ **C**, −**c**_i ∈ **C**. ✓
- **First moment vanishes:** Σ_i **c**_i = (0, 0, 0). ✓ (Each ± pair sums to 0;
  the rest vector is 0.)
- **No corner vectors:** ∀**c**_i ∈ **C**, ‖**c**_i‖² ≤ 2. ✓

## 3. The weights ω_i

### 3.1 Definition

For the D3Q19 lattice, the weights partition by velocity class:

> ω_rest = 1/3
> ω_face = 1/18 (for each of the 6 face-neighbor directions)
> ω_edge = 1/36 (for each of the 12 edge-neighbor directions)

In the canonical ordering above:

| Indices | ω_i |
|---:|:---|
| 0 | 1/3 |
| 1–6 | 1/18 |
| 7–18 | 1/36 |

### 3.2 Derivation

The weights are determined by requiring the discrete velocity set to satisfy
the second-order Gauss-Hermite quadrature condition on the
Maxwell-Boltzmann equilibrium distribution. Concretely:

**Constraint 1 — Normalization:** Σ_i ω_i = 1.

**Constraint 2 — First moment vanishes:** Σ_i ω_i **c**_i = **0**.
(Automatically satisfied by the symmetry of **C**.)

**Constraint 3 — Second moment is isotropic with c_s² = 1/3:**
Σ_i ω_i c_iα c_iβ = (1/3) δ_αβ, for α, β ∈ {x, y, z}.

**Constraint 4 — Third moment vanishes:** Σ_i ω_i c_iα c_iβ c_iγ = 0.
(Automatically satisfied by the symmetry of **C**.)

**Constraint 5 — Fourth moment is isotropic:**
Σ_i ω_i c_iα c_iβ c_iγ c_iδ = (1/9)(δ_αβ δ_γδ + δ_αγ δ_βδ + δ_αδ δ_βγ).

Treating ω_face and ω_edge as unknowns with ω_rest = 1 − 6ω_face − 12ω_edge
(from Constraint 1), Constraints 3 and 5 give a 2×2 system whose unique
solution is ω_face = 1/18 and ω_edge = 1/36, yielding ω_rest = 1/3.

### 3.3 Sanity checks

- **Normalization:** 1·(1/3) + 6·(1/18) + 12·(1/36) = 12/36 + 12/36 + 12/36 = 36/36 = 1. ✓
- **Second moment (xx component):** contributions come from directions with
  c_x ≠ 0, i.e., directions 1, 2 (face ±x; c_x² = 1, ω = 1/18 each) and
  7, 8, 9, 10, 11, 12, 13, 14 (eight edge directions with c_x² = 1, ω = 1/36 each).
  Total: 2·(1/18)·1 + 8·(1/36)·1 = 2/18 + 8/36 = 4/36 + 8/36 = 12/36 = 1/3. ✓
- **Lattice sound speed:** c_s² = 1/3 (from Constraint 3). c_s = √(1/3) ≈ 0.5774
  in lattice units.

## 4. The equilibrium distribution

### 4.1 Definition

The discrete-velocity Maxwell-Boltzmann equilibrium, expanded to second order
in the Mach number u/c_s, is:

> f_i^eq(ρ, **u**) = ω_i ρ · [ 1 + 3(**c**_i · **u**) + (9/2)(**c**_i · **u**)² − (3/2)(**u** · **u**) ]

where ρ is the macroscopic density, **u** is the macroscopic velocity, and
both are in lattice units (i.e., c_s² = 1/3 absorbed into the numeric
coefficients 3 = 1/c_s², 9/2 = 1/(2 c_s⁴), 3/2 = 1/(2 c_s²)).

This is the **compressible** form (matches Krüger chapter13/cpu/LBM.cpp:97

and chapter13/cpu_intro/main.cpp:271). The incompressible-linearized form
(chapter5/poiseuille_BB.m:93) is not adopted by Phase 12.

### 4.2 Canonical test points

The cat3 numerical-correctness check evaluates the GPU shader's `feq()`
function at the following input points and compares against the expected
output values to tolerance `tolerance_relative = 1.0e-6`,
`tolerance_absolute = 1.0e-9`. All values are computed in double-precision
arithmetic from the formula above; the GPU shader is expected to compute
in single-precision and match within tolerance.

#### Test point 1: zero velocity

> Input: ρ = 1.0, **u** = (0, 0, 0)
> Expected: f_i^eq = ω_i for all i.

i.e., (1/3, 1/18, 1/18, 1/18, 1/18, 1/18, 1/18, 1/36, 1/36, …, 1/36).

This validates that the implementation handles density scaling correctly.

## 5. Halfway bounce-back boundary condition

For solid-wall obstacle nodes (e.g., the NACA airfoil voxelized into a
3D r8 mask in Phase 12), the no-slip condition is enforced via halfway
bounce-back: after streaming, populations that would have streamed INTO
a solid node are reflected back into the adjacent fluid node along the
opposite direction.

Reference pattern: `references/lbm-principles-practice/chapter5/poiseuille_BB.m:123`
(D2Q9 version; the 3D generalization uses the opposite-direction pairs
listed in § 2.2 of this document).

The 3D bounce-back operation, for a fluid node **x** with a solid neighbor
at **x** + **c**_i (i.e., the population f_i streamed from **x** has hit a
solid):

> f_{opp(i)}(**x**, t+1) ← f_i^*(**x**, t)

where f_i^* is the post-collision pre-streaming population at **x**, and
opp(i) is the opposite-direction index per the involution in § 2.2.

This is second-order accurate in space (the wall is implicitly placed
halfway between the fluid node and the solid node along the lattice link).

## 6. Verification posture

The cat3 numerical checks consuming this derivation:

- **`cat3.d3q19-velocity-set`** — verifies that the GPU shader's `c_i` table
  matches the 19 vectors in § 2.2 byte-for-byte (HARD_FAIL).
- **`cat3.d3q19-weights`** — verifies that the GPU shader's `w_i` table
  matches the values in § 3.1 within `1e-9` absolute tolerance (HARD_FAIL).
- **`cat3.d3q19-equilibrium`** — evaluates the shader's `feq()` at the
  test points in § 4.2 and compares against the algebraic expected values
  within `1e-6` relative / `1e-9` absolute tolerance (SOFT_WARN by default,
  HARD_FAIL via per-check upgrade per spec § 5).

The check implementations live in `tools/integrity/integrity/cat3_numerical/checks/`;
this document is their ground-truth source.
